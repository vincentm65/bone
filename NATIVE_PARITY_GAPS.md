# Native ↔ TUI Parity Gap Tracker

Verified gaps between the TUI (`tui/`, binary `bone`) and the native egui app
(`native/`, binary `bone-desktop`). Native should match the TUI closely.

Each item: **ID — title** (severity). Evidence cites real `file:line`. Fix is the
intended approach; "Done when" is the acceptance check.

Legend: `[ ]` open · `[~]` in progress · `[x]` done · `[!]` blocked

> **Note on `NATIVE_PARITY_PLAN.md`.** Its Phase 1/2 claims are inaccurate: it
> marks `/help`, `/clear`/`/new`, `/model`, `/provider` done, but native
> implements none of them client-side and the daemon cannot run them. This file
> supersedes it for gap tracking.

## Tier 1 — broken / dead state (bugs)

### N-01 — Most built-in slash commands are dead in native (critical)
- **Evidence:** `native/src/main.rs:356-402` intercepts only `/update`, `/edit`/`/e`, `:`/`!`; everything else goes to the daemon as `RunCommand`. The daemon only finds Lua handlers (`core/src/rpc/mod.rs:1660-1690`) and built-ins are protected from Lua (`core/src/commands.rs:34-38`); only `config.lua` exists. So `/help`, `/clear`, `/new`, `/model`, `/provider`, `/stats`, `/setup`, `/catalog`, `/quit`, `/exit`, `/tools`, `/incognito` all return `unknown command: <name>`. Autocomplete still advertises them (`native/src/commands.rs:12-32`).
- **Fix:** Intercept built-ins client-side in `submit_composer` like the TUI (`tui/src/ui/app/mod.rs:3708-3963`): route to existing dialogs (`/stats`→stats, `/setup`→setup, `/catalog`→catalog, `/model`/`/provider`→provider dialog, `/clear`/`/new`→new conversation, `/incognito`→toggle, `/quit`/`/exit`→close, `/config`→config dialog), add a real `/help`, and stop autocomplete from listing anything unimplemented.
- **Done when:** every name in `BUILTINS` either performs its action or is not offered; `/help` renders a command + shortcut reference; no built-in yields `unknown command`.

### N-02 — Token usage and WorkElapsed stored but never rendered (high)
- **Evidence:** `state.token_usage` / `state.work_elapsed_ms` have no readers outside `native/src/state.rs` (grep-verified). TUI shows live in/out/context in the status bar (`tui/src/ui/app/stream/mod.rs:909,1109-1126`) and a "worked for …" notice (`:1171-1172`).
- **Fix:** Render per-turn tokens (in/out/total/context) and elapsed in the status row; add the end-of-turn "worked for" transcript notice.
- **Done when:** a completed turn shows token counts and elapsed time in native, matching TUI.

### N-03 — Configurable keymap ignored (high)
- **Evidence:** zero `keymap`/`KeymapDispatch`/`KeymapDispatched` references in `native/src` (grep). TUI routes keys through the daemon keymap (`tui/src/ui/app/keymap.rs:15-96`); native keys are hardcoded.
- **Fix:** Consume the daemon keymap (dispatch → apply `KeymapDispatched`) for the actions native can perform; fall back to current hardcoded defaults.
- **Done when:** a user keybinding in config triggers the same action in native as in TUI.

### N-04 — Theme parsed but largely unused (high)
- **Evidence:** full palette parsed (`native/src/theme.rs:18-40`) but chat/markdown/shell use hardcoded colors (`native/src/transcript.rs:355-358`; `native/src/markdown.rs` has no theme usage). Named colors dropped — `parse_color` accepts only `#hex` (`native/src/theme.rs:150-185`). `diff_added`/`diff_removed` never applied.
- **Fix:** Thread the parsed palette into transcript/markdown/shell rendering; accept named/ANSI colors and palette-role references like `tui/src/ui/color.rs`.
- **Done when:** changing theme colors (incl. named values) visibly changes native chat/markdown/tool styling.

### N-05 — Markdown gaps (high)
- **Evidence:** no `syntect` dep; code blocks are plain monospace (`native/src/markdown.rs:400-442`). Only strikethrough enabled (`:107`) — no tables/task lists/footnotes. No diff preview (+/- coloring, gutters) in `transcript.rs`/`markdown.rs`. TUI has all (`tui/src/ui/render/markdown.rs:270-303`; `tui/src/ui/render/messages.rs:798-850`).
- **Fix:** enable tables/tasklists/footnotes; add syntax highlighting; render diff previews with line-number gutters.
- **Done when:** a message with a table, task list, highlighted code block, and a diff renders as in the TUI.

### N-06 — No reasoning display control (medium)
- **Evidence:** reasoning always streams inline (`native/src/state.rs:492`); TUI has `show_thinking` toggle + live bounded pane (`tui/src/ui/app/stream/mod.rs:1103-1111,1418-1428`).
- **Fix:** honor `show_reasoning`; add a live (collapsed) thinking affordance.
- **Done when:** reasoning is hidden when the config says so, and shown live otherwise.

- [x] **N-18 — Catalog is one-click-per-item** (medium). `catalog::CatalogView` keeps a persistent multi-select (`checked`/`touched`/`results`/`banner`): installed/update-available rows seed checked, Select all/Clear all buttons, a single "Apply N changes" batch sends only touched rows differing from the snapshot, and the response drives an in-popup result phase (per-item installed/removed/failed tags + banner, cleared by Done). - [x] **N-19 — No typed `/catalog install|remove NAME`** (low). Already implemented: `DesktopApp::apply_catalog_command` (`native/src/main.rs`) mirrors the TUI; `/catalog` with an arg routes to `UiRequest::CatalogAction`.

### Setup / platform
- [x] **N-20 — Wizard is a single dialog** (medium). Dismissing while still actionable and never applied sets a sidebar notice to reopen from the menu or `/setup` (addresses the no-re-prompt gap). +5 setup tests.
- [x] **N-21 — No credential validation before save** (medium). `setup::SetupUi` now validates the entered API key client-side before Apply: `key_error()` flags a blank key when a provider is selected (`missing_key_warning` otherwise) and rejects a too-short/obviously-malformed value, `can_apply()` gates the footer's `add_enabled` Apply button, and the Provider/Confirm steps render the inline error. Skipping the provider step stays allowed. +setup tests.
- [x] **N-22 — No CLI at all** (medium). New `native/src/cli.rs` (`Command{Gui,Version,Help,DaemonSide}`, `Cli`, `parse`, `version`, `usage`, loopback address validation via `daemon::ensure_port`/`local_endpoints`). `main()` parses `std::env::args`, prints version/usage, rejects daemon-side subcommands (`connect`/`serve`/`web`/`run`/`install`/`update`) with a pointer to `bone` + exit 2, and launches the GUI with the parsed options. `DesktopApp::apply_cli` sets the address, opens `setup`/`catalog`/`stats-popup` dialogs, and stages `--provider`/`--model`; `apply_cli_overrides` (each frame) switches the provider once the config snapshot is known, then sets the model only after it is active; `ensure_open_dialog_data` retries dialog fetches until a tab connects. +12 tests (9 cli + 3 app). Remote connect still rejected.

## Tier 3 — polish / parity

- [x] **N-23 — Shell rows unstyled** (low). Shell tool rows now render through `render_shell_body` (`native/src/transcript.rs`): `shell_output_lines` strips the `exit code:`/`stdout:`/`stderr:` framing and merges the streams (dropping trailing blanks), the body gets the TUI `│`/`╰` gutter (error-colored on failure), and a collapsed row shows first two + `⋮ +N terminal lines` + last two while expanded output stays chunk-bounded (`CHUNK_LINES`). Generic tools keep the preformatted block. +1 render/unit test. (Bash syntax highlighting deferred: `markdown::code_layout_job` is private and low-value here.)
- [x] **N-24 — No word-wrap for preformatted content** (low). Code-block bodies and `preformatted_frame` now use `TextWrapMode::Wrap` instead of `Extend` (`native/src/markdown.rs`, `native/src/transcript.rs`); table cells intentionally stay `Extend`.
- [x] **N-25 — Status bar sparse** (low). Per-tab status row (`native/src/main.rs`) now shows a spinner while `busy`, the active `provider/model` label (hover: "Active provider model"), and a `N running · M job(s)` strip when any process is running or jobs exist, alongside the existing token/elapsed counters.
- [x] **N-26 — Transient notices not persisted** (low). `State::reduce` now appends `system` rows for `ConversationLoadFailed` ("Load failed: …"), `Failed` ("Failed: …"), and `StreamLagged` ("Repairing missed events…"), so they persist in the transcript instead of only flashing in the status bar (`native/src/state.rs`). +1 test.
- [x] **N-27 — System messages dropped on replay** (medium). Verified parity, no code change: both native (`state.rs::replace`) and the TUI (`rebuild_scrollback_from_transcript`) skip `ChatRole::System` on history replay, and the provider history's system prompt is a `System` message; rendering it would diverge from the TUI.
- [x] **N-28 — No input-style presets** (low). `state::InputStyle` parses `ui.input` from the resolved settings (`preset` lines/box/filled, `prefix`, `show_prefix`, horizontal/vertical padding clamped to 8, `fill`) and `composer_panel` wraps the editor in the matching `egui::Frame` + prefix (`native/src/state.rs`, `native/src/main.rs`). +1 test.
- [x] **N-29 — Missing editor shortcuts** (low). `composer_panel` now opens the editor on Ctrl+X and cancels a running turn on Ctrl+C via `consume_event`, because egui-winit delivers these as `Event::Cut`/`Event::Copy` (never `Event::Key`); both are gated on editor focus with no active text selection so normal editing still works.
